---
title: Output
description: output is the contract for what a function returns to whoever calls it.
---

```ts
// What callers get back: the row without internal columns
export const Booking = createSelectSchema(bookings).omit({
  accountId: true,
});

/** Get a booking */
export const get = query({
  input: z.object({ bookingId: z.uuid() }),
  output: Booking,
  authorize: staff,

  // Returns the whole row; accountId is stripped
  handler: (ctx, input) => findBooking(ctx, input.bookingId),
});
```

- **Declare it on what you publish.** What leaves your process, to a browser, an oRPC client or an AI agent, is a contract, and an oRPC client's types come from it.
- **The result is parsed against it.** Unknown keys are stripped (Zod objects strip by default), so returning a whole row can't leak a column.
- **It's optional.** Without it, callers get the handler's return value, all of it, typed as the handler's return type. Fine for internal functions, whose result only reaches your own code. For a published one, it's how a column you didn't mean to send gets out.
- **Invalid output is a bug in your code**, not a bad request: it throws like any bug. `toResponse` and the AI adapter never send it to a client as-is.

`createSelectSchema` comes from `drizzle-orm/zod`. Any Standard Schema works.
