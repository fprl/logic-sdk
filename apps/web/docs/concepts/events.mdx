---
title: Events
description: Emitted inside a mutation, delivered to listeners only after commit.
---

```ts
// bookings/events.ts
export const confirmed = event({
  payload: z.object({ bookingId: z.uuid() }),
});

// bookings/mutations.ts, inside a mutation
ctx.emit(confirmed, { bookingId });

// tasks/listeners.ts
export const prepareStay = listener({
  event: () => bookings.confirmed,
  description: "Create the handover task and email the guest",
  async handler(ctx, payload) {
    await ctx.run(tasks.create, { bookingId: payload.bookingId, title: "Prepare the house" });
    await ctx.services.mailer.send(...);
  },
});
```

- **Delivered only after commit.** A rolled-back mutation emits nothing.
- **Each listener runs like an action**, so every mutation it runs commits on its own.
- **A failing listener never fails the caller.** The error goes to `onError`.
- **`event` is a thunk** (`() => bookings.confirmed`), so two modules can import each other's index without an import-cycle crash.
- **What you emit is what's delivered.** `emit` takes a snapshot of the payload.
- **Listeners must be idempotent.** They may run again; `ctx.event.id` is the key to dedupe on.
- **Listeners run with the emitter's scope.** Have them run internal functions, not exposed ones. See [Authorization](/docs/concepts/authorization#nested-calls-and-listeners).

## Serverless

On serverless platforms, give the registry `waitUntil` so the response returns right after commit and listeners finish afterwards. Without it, `run` waits for the listeners, which is what you want in tests and long-lived servers.

**Next.js:** create the registry once, and hand delivery to `after`:

```ts
import { after } from "next/server";

export const registry = createRegistry({
  modules,
  database,
  waitUntil: (p) => after(() => p),
});
```

**Cloudflare Workers:** with Hyperdrive, the database client is per request, so the registry is too. Take `waitUntil` from the execution context:

```ts
export default {
  async fetch(request, env, ctx) {
    // Hyperdrive pools connections: a client per request is the recommended setup
    const sql = postgres(env.HYPERDRIVE.connectionString, { max: 5 });
    const registry = createRegistry({
      modules,
      database: drizzleAdapter(drizzle({ client: sql })),
      waitUntil: (p) => ctx.waitUntil(p),
    });
    ...
  },
};
```

**Node:** create the registry once at startup. No `waitUntil` needed.

## Loops

A listener whose mutation emits the event it listens to would loop forever. Delivery stops after **8** hops (`maxEventDepth`) and the loop is reported to `onError`. Real chains are 2 or 3 hops.

## Durability

The default dispatcher delivers in-process, right after commit. If the process crashes between commit and delivery, the events are lost. The seam for a durable outbox exists: `enqueue(tx, envelopes)` runs inside the transaction, and a worker calls `registry.dispatch(envelope)`, which throws if any listener failed, so the worker can retry.
