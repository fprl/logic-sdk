Logic SDK is for the layer between your routes and your database: the business logic. You write it once, as plain declarations, and call it from anywhere: an HTTP route, a Server Action, a queue worker, a script, a test or an AI agent.

```ts
/** Confirm a pending booking */
export const confirm = mutation({
  input: z.object({ bookingId: z.uuid() }),
  output: Booking,
  authorize: staff,

  async handler(ctx, input) {
    const booking = await findBooking(ctx, input.bookingId);
    if (booking.status !== "pending") {
      throw ctx.errors.reject("not_pending");
    }

    // Another module, in the same transaction
    await ctx.run(availability.hold, rangeOf(booking));

    // Delivered to listeners only after commit
    ctx.emit(confirmed, { bookingId: input.bookingId });

    return setStatus(ctx, booking.id, "confirmed");
  },
});
```

Bind who is calling once, then run anything:

```ts
const caller = registry.as({ actor, accountId });

await caller.run(bookings.confirm, { bookingId });
```

## What you get

- **One transaction across modules.** A mutation and every mutation it runs commit together. A failure anywhere rolls back everything.
- **Side effects after commit.** Mutations emit events, and listeners send the email once the data is safe.
- **Who is calling, everywhere.** The scope you bind reaches every nested call and listener. Policies narrow its type.
- **Authorization on every call.** A function's `authorize` policy runs whoever calls it: HTTP, an agent, a job or another function.
- **Internal by default.** A function reaches clients only when you publish it: in your oRPC router or an agent's tools, which refuse one without `authorize`, or from your own route, which should only call functions that have one.
- **Tests without mocks.** Each test is a real transaction on a real database, always rolled back.
- **Any runtime.** Node, Bun and Cloudflare Workers, under any framework. No decorators, classes, codegen or build step.

## Four kinds of functions

| | Use it for | Transaction | Can run |
|---|---|---|---|
| `query` | Reading data | The caller's, if any | Queries |
| `mutation` | Changing data | One, joined by nested mutations | Queries and mutations |
| `action` | Payments, email, AI, any network call | None | Anything |
| `listener` | Reacting to another module's event | None, runs after commit | Anything |

Services (a mailer, a payment client) only reach actions and listeners. A mutation can roll back, and an email sent from inside it can't be unsent.
