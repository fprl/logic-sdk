```ts
// test/setup.ts, or the top of a test file
import { createTestRegistry } from "logic-sdk/testing";

export const mailer = memoryMailer();
export const t = createTestRegistry(registry, {
  services: { mailer },
  now: "2026-07-01T10:00:00Z",
});

beforeEach(async () => {
  mailer.sent.length = 0;
  await t.begin();
});
afterEach(() => t.rollback());
```

```ts
test("confirm holds the dates and emails the guest", async () => {
  const agent = t.as(scopeAs("agent"));

  await agent.run(bookings.confirm, { bookingId });

  expect(t.events.map((e) => e.name)).toEqual(["bookings.confirmed"]);
  expect(await t.db.select().from(holds)).toHaveLength(1);
  expect(mailer.sent).toHaveLength(1);
});
```

- **Real database, no mocks.** Each test is a transaction that's rolled back. Every top-level mutation inside it becomes a savepoint, so a failing mutation rolls back only its own writes, as in production.
- **Set up once, with hooks:** in a setup file for every test, or at the top of each file. Without `begin`, `t` throws and says so, instead of writing to your database.
- **Arrange with real functions**, not inserts, so test data goes through the same rules.
- **Swap services** for in-memory ones, and reset them in `beforeEach`. Freeze time with `now`.
- **Change settings** with `config: { orders: { maxItems: 1 } }`. It merges section by section over the registry's [config](/docs/concepts/config). A test registry with other settings gets its own file.
- **`t.events`** records every event, delivered or not.
- **`t.stub(fn, impl)`** replaces one function for the current test, for example to simulate another module failing:

```ts
t.stub(availability.hold, async () => {
  throw new Error("calendar service down");
});
```

- **`t.registry`** is bound to the test's transaction, so adapters run in the same rollback: an oRPC router's context is `{ caller: t.registry.as(scope) }`.
- **One test at a time per `t`:** they share one connection. `test.concurrent` makes `begin` throw.

## Jobs in tests

Your app's adapter (a database queue, an outbox, Cloudflare) is never used in tests. You pick one of two modes:

```ts
const t = createTestRegistry(registry, { jobs: "manual" }); // default: "inline"

test("confirming queues the receipt without sending it", async () => {
  await t.as(agent).run(bookings.confirm, { bookingId });

  expect(t.jobs.queued.map((j) => j.listener)).toEqual(["notifications.sendReceipt"]);
  expect(mailer.sent).toEqual([]);

  await t.jobs.drain(); // run what's queued, and what that queues
  expect(mailer.sent).toHaveLength(1);
});

test("the receipt email", async () => {
  await t.jobs.perform(notifications.sendReceipt, { bookingId }, { scope: agent });

  expect(mailer.sent).toHaveLength(1);
});
```

- **Inline** runs listeners right after each mutation, inside the test, one try.
- **Manual** keeps jobs in `t.jobs.queued` until `drain()`, to test one module without the others reacting.
- **`tick(at)`** runs the [crons](/docs/concepts/crons) due at that minute, inline in both modes.
- **`perform`** runs one listener by hand, as if its event had been emitted as `scope`.
- **What waits, waits for `drain()`,** in both modes: a listener's `delay` (in `t.jobs.queued`) and `ctx.schedule` (in `t.jobs.scheduled`). `drain()` runs what's due at the test's `now`; `drain({ until })` runs what's due by then, each job at the time it was due (that's what its `ctx.now()` reads).
- **The test registry holds what your app's adapter holds:** on `inProcess()`, `ctx.schedule` throws in tests too, as it would in production. Build it from the registry your app runs, so `createRegistry`'s checks (like `jobs.scope.load` for a database queue) run in tests too.
- **A failing listener fails the test.** `run`, `drain` and `perform` throw its error, so a test can't pass over it; one that ran through `t.registry` (an adapter's call) makes `rollback` throw. The mutation still committed, as in production. A job `jobs.scope.load` discards doesn't throw: `perform` resolves `"discarded"`. `load` reads through `ctx.db`, the test's transaction, so a job for an account the test created isn't discarded.

```ts
test("confirming schedules a reminder the day before", async () => {
  await t.as(agent).run(bookings.confirm, { bookingId });

  expect(t.jobs.scheduled.map((j) => [j.fn, j.runAt])).toEqual([["guests.remind", "2026-07-09T09:00:00.000Z"]]);
  await t.jobs.drain({ until: "2026-07-09T09:00:00Z" });
  expect(mailer.sent).toHaveLength(1);
});
```

## Which database

`examples/bookings` runs its suite on PGlite by default: the real Postgres engine in WASM, in-process, no Docker. It runs one connection at a time, so it can't show concurrency bugs. With `DATABASE_URL` set, the same suite runs on real Postgres, through the production driver, including a race test. CI always sets it.
