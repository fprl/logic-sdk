---
title: HTTP routes
description: Your own routes call your functions; toResponse turns a domain error into its status.
---

Write routes the way your framework does, and call the function from them. Your routes are your API surface: a function no route calls isn't reachable over HTTP.

```ts
import { toResponse } from "logic-sdk/fetch";

// Hono
app.post("/orders", async (c) => {
  try {
    return c.json(await c.var.caller.run(orders.place, await c.req.json()), 201);
  } catch (e) {
    return toResponse(e);
  }
});
```

- **`toResponse(error)` handles domain errors:** `{ "error": { "kind", "code", "details" } }`, with the status from the table below.
- **Anything else is thrown again,** so your framework makes the 500 and logs it, and the message never reaches the client. Hono's default handler answers a plain `Internal Server Error` and logs the error.
- **Or once, for every route:** `app.onError((e, c) => (isDomainError(e) ? toResponse(e) : c.text("Internal Server Error", 500)))`.
- **The caller is the request's:** build it in a middleware, `registry.as(await scopeFrom(c.req.raw))`, and keep the scope's policies doing the deciding. A function with `authorize` checks it on every call, from a route too.

Elsewhere, check what your framework sends for an uncaught error before you rely on it. In a Next.js route handler, say it yourself:

```ts
// app/orders/route.ts
export async function POST(request: Request) {
  try {
    return Response.json(await callerFor(request).run(orders.place, await request.json()), { status: 201 });
  } catch (e) {
    if (isDomainError(e)) return toResponse(e);
    console.error(e);
    return Response.json({ error: { kind: "internal" } }, { status: 500 });
  }
}
```

## Statuses

| Kind | Status |
|---|---|
| `invalid` | 400 |
| `unauthenticated` | 401 |
| `forbidden` | 403 |
| `not_found` | 404 |
| `conflict` | 409 |
| `rejected` | 422 |

The map is exported as `statusOf`.

## Signed out

- **A route that also serves public functions:** build the caller with a scope that has no actor. Functions whose `authorize` needs one answer 403.
- **A route that's entirely session-only:** throw `unauthenticated()` (from `logic-sdk`) before the caller is built, and `toResponse` makes it a 401.

```ts
import { unauthenticated } from "logic-sdk";

const session = await auth.getSession(request);
if (!session) throw unauthenticated();
```

## A typed client

For a typed client, OpenAPI or MCP, publish through [oRPC](/docs/adapters/orpc) instead of hand-written routes.

## Serverless

Listeners can finish after the response: set `waitUntil` once on the registry. See [Events](/docs/concepts/events#serverless).
